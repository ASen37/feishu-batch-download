# 飞书文档批量导出

把飞书知识库文档及其所有子文档**递归**批量导出为 PDF / Word / Markdown，
按飞书里的目录结构分文件夹保存。产物由飞书服务端渲染，与网页上手动导出**逐字一致**。

v0.3 起改为**调用飞书自己的导出接口**：浏览器只在首次登录时出场一次，
之后全是纯 HTTP —— 查文档树、提交导出任务、轮询、下载，不渲染任何页面。
一次跑十几篇文档，从「一篇篇开页面等渲染」变成「一轮并发请求」。

支持导出正文评论、Markdown 带附件（正文 + 图片打包，自动解压）等选项，
细节见下方「导出格式」。

## 使用前提
1. 已安装 [uv](https://docs.astral.sh/uv/)
2. 本机网络可访问飞书
3. 本机装有 Chrome 或 Edge（Windows 自带 Edge，所以一般不用额外装东西）
4. **要有一个能看这个知识库的飞书账号**，首次运行需在弹出的窗口里登录一次

> ⚠️ **必须真的登录**，不能只输访问密码 —— 原因见下方「为什么必须登录」。

## 初始化

**只需安装 Python 依赖；浏览器用本机的 Chrome / Edge，不用下载内核：**
```bash
uv sync
```

> 只有当你想用 Playwright 自带内核时（`browser` 设为 `chromium`，或者本机
> 既没 Chrome 也没 Edge），才需要额外运行：
> ```bash
> uv run playwright install chromium
> ```

## 使用

### 链接怎么给：给最顶层的根文档

工具是**从你给的这一篇往下递归**的，所以链接给错会直接反映在结果上，跑之前先看一眼：

**给最顶层的根文档。** 给中间某一篇，就只拿到它那棵子树 —— 同级的兄弟章节
一篇都不会下来，而且**不报错**，看着像正常跑完了。想确认给的是不是根：打开知识库，
左侧目录树里最上面那一篇（通常叫「首页」）就是根。

> 飞书点「复制链接」拿到的地址会带一串 `?from=from_copylink`，**这个不用管** ——
> 程序会自己剥掉。要是报 `[920004002] SourceNotExist`，那是别的原因，见「排查」。
>
> 命令行里传链接时建议加**引号**包起来：链接里的 `&` 在部分终端会被当成分隔符。

### 1. 最简单的方式：双击 `start.bat`

会依次问你「要下载哪个链接」，然后自动跑完。首次运行还需要在弹出的浏览器里
登录一次飞书账号。窗口结束前会停住，方便你看结果。

```
start.bat                 双击运行，或命令行直接跑
start.bat <文档链接>       直接指定链接，跳过询问
start.bat --force         参数原样透传给 main.py
```

### 2. 命令行方式

**首次运行（有头模式，需手动登录一次）：**

```bash
uv run python main.py
```
浏览器弹出 → 在浏览器里登录飞书账号 → **程序会自己发现登录完成，不用按回车**
→ 凭证缓存到 `.feishu_session.json`，浏览器关闭，之后全部走 HTTP。

**之后直接跑（不会再弹浏览器）：**

```bash
uv run python main.py
```

**更换下载链接：**
```bash
uv run python main.py <新链接>
```
新链接会自动写入 `config.json`，以后直接 `python main.py` 即可。

### 3. 命令行参数一览

```
uv run python main.py [文档链接] [参数]
```

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `<文档链接>` | 指定要下载的根文档 | 会写进 `config.json`；不填则用已存的那个 |
| `--format` | 导出格式：`pdf` / `word` / `md` | 写 `docx`、`markdown` 也认 |
| `--comments` | Word/PDF：**导出正文及评论** | 默认不带评论 |
| `--no-comments` | Word/PDF：仅正文（默认） | |
| `--attachments` | Markdown：**带附件的全部内容**（默认） | 图片、附件都在 |
| `--no-attachments` | Markdown：仅文本 | 不含图片和附件 |
| `--out` | 本地保存目录 | 默认 `downloads`；相对路径相对于程序所在目录 |
| `--force` | 忽略增量清单，**全部重新下载** | 已经下过、文件也还在的，照样重下 |
| `--relogin` | 丢弃**凭证缓存**，强制重新登录 | 只清 `.feishu_session.json`，**不动浏览器登录态** |
| `--reset` | 清空**全部登录状态**，彻底重来 | 凭证 + 浏览器 profile 一起清，见下方说明 |
| `--diag` | 只查文档树、打印节点表，**不下载** | 排查「抓不到文档」时用，会列出每篇的 obj_token |
| ⚠️ | `--diag` **不是完全只读** | 只要你**在命令行传了链接**，那个链接就会被写回 `config.json` —— 拿别的链接试诊断会把正在用的链接换掉 |
| `--headless` | 无头模式 | 浏览器不显示窗口，仅在需要登录时用到 |
| `-h`, `--help` | 显示帮助 | |

> `--format` / `--comments` / `--attachments` / `--out` 给过一次就会**写回
> `config.json`**，下次不带参数直接跑即可沿用。双击 `start.bat` 时也会用问答的
> 方式问同样几项。

### 导出格式

| 格式 | 命令行 | 产物 | 该格式的选项 |
| --- | --- | --- | --- |
| PDF | `--format pdf` | `.pdf` | `--comments` / `--no-comments` |
| Word | `--format word` | `.docx` | 同上 |
| Markdown | `--format md` | `.md` | `--attachments` / `--no-attachments` |

各项默认值按最常用的来：**Word/PDF 不带评论，Markdown 带附件的全部内容。**
两种格式的选项互不相干 —— 导 Markdown 时评论开关不参与，反之亦然，
所以来回切格式不会互相触发重下。

#### Markdown「带附件」下下来是个压缩包

选「带附件的全部内容」时，飞书给的不是 `.md`，而是一个 **zip**：

```
预习任务-提前安装软件.zip
├── 预习任务-提前安装软件.md      ← 正文
└── 图片和附件/image.png          ← 47 张图
```

程序会**自动解开**，并把正文改成跟文件夹同名，落在文档自己的文件夹里：

```
downloads/Day01_项目环境-Linux/
└── 预习任务-提前安装软件/
    ├── 预习任务-提前安装软件.md    ← 图片链接相对指向 图片和附件/，解压后仍连得上
    └── 图片和附件/
        └── …47 张
```

**为什么每篇都要单独一个文件夹**：压缩包里那个附件目录名是**固定的**
（就叫「图片和附件」）。两篇文档要是落在同一个父目录下，图片会互相覆盖。
这跟「有子文档的父文档折进自己文件夹」是同一个思路。

**注意**：`--no-attachments`（仅文本）保持单个扁平 `.md`，不套文件夹 ——
没有附件就没有撞名问题。

> 顺带一提：**同一档选项下，产物形态可能不一样**。没有图片/附件的文档
> 即使选了「带附件的全部内容」，飞书给的也是普通 `.md`。程序按选项决定
> 落点（多包一层文件夹），按**文件头**决定要不要解压 —— 两者分开处理，
> 所以有没有附件都不会出错。

```bash
uv run python main.py --format md                    # 导成 Markdown（默认带附件）
uv run python main.py --format word --comments       # 导 Word，含评论
uv run python main.py --format pdf --out D:\飞书文档   # 换个保存目录
```

可以组合使用：

```bash
uv run python main.py                    # 用 config.json 里存的链接
uv run python main.py <新链接>            # 换个链接下载
uv run python main.py --force            # 全部重新下载
uv run python main.py <新链接> --diag     # 先看看这个链接下有哪些文档
uv run python main.py --reset            # 彻底重来（清空登录状态）
```

## 浏览器与登录

### 用哪个浏览器

由 `config.json` 的 `browser` 决定，默认 `auto` —— **按顺序自动找第一个能用的**：

| 顺序 | 值 | 说明 |
| --- | --- | --- |
| 1 | `chrome` | 本机 Google Chrome |
| 2 | `msedge` | 本机 Microsoft Edge（Windows 自带，通常不用装） |
| 3 | `custom` | `browser_path` 指向的 Chromium 内核浏览器 |
| 4 | `chromium` | Playwright 自带内核（需 `playwright install chromium`） |

也可以强制指定某一个，比如 `"browser": "msedge"`。填了不认识的值、或者
`custom` 却没配 `browser_path`，都会自动退回 `auto` 并在日志里说明原因。

启动日志会明说最后用的是哪个：

```
正在启动浏览器
  候选顺序：本机 Google Chrome → 本机 Microsoft Edge → Playwright 自带 Chromium
  ✗ 本机 Google Chrome 起不来：...
浏览器启动完成（本机 Microsoft Edge）。
```

> **不保证支持国产浏览器**（360、QQ 等）。Playwright 只认 chrome / msedge /
> chromium 这几家官方渠道；用 `browser_path` 硬指过去也许能跑，但不保证，
> 真出问题会很难查。

### 登录状态是独立的

程序用的是**自己的用户数据目录**（`.browser_profile/`），跟你平时用的浏览器
**不是同一套登录状态**。

所以「我 Chrome 里明明登录过飞书了」**不算数** —— 得在弹出的那个窗口里
**再登一次**。只需这一次，之后凭证缓存在 `.feishu_session.json`，正常不会再弹。

各浏览器的 profile 分开存放（Chrome 沿用 `.browser_profile/`，其余用
`.browser_profile/<浏览器名>/`），免得不同浏览器的 profile 格式互相打架。
**换了浏览器 = 需要重新登录一次。**

### 为什么必须登录（只输访问密码不够）

有些知识库**凭访问密码就能匿名阅读** —— 没登录也能打开里面的单篇文档，
正文照样显示，跟登录后的样子一模一样。

但匿名身份有个硬限制：**列不出整棵文档树**。

| 动作 | 匿名读者（只输过访问密码） | 已登录的成员 |
| --- | --- | --- |
| 打开某一篇文档 | ✅ | ✅ |
| 列出知识库的文档树 | ❌ `[920004004] PermFail` | ✅ |

而本工具靠「列出文档树」来发现子文档 —— 拿不到树，就只能导出第一层。
实测一个 41 篇的知识库，匿名身份只导出了 15 篇，**而且不报错**，看起来
就像正常跑完了。

所以程序现在会**主动实测登录态**，并且**验收**拿到手的凭证：

- 打开文档前，先访问一个必须登录才能进的页面，确认身份合格；
- 没登录就把浏览器停在登录页，等你扫码/输手机号，登完自动继续；
- 拿到凭证后当场真调一次文档树接口，列不出来就重试，始终不行就**停下报错**，
  不会再带着不合格的身份往下跑。

> 一句话：**访问密码只是「进某一篇的门」，登录才是「看整个知识库的钥匙」。**

### 怎么清空登录状态、彻底重来

登录态存在**两个地方**，只删一个往往不够：

| 位置 | 存什么 | 删了会怎样 |
| --- | --- | --- |
| `.browser_profile/` | **浏览器的 profile —— 真正的登录态在这** | 浏览器变回未登录，要重新扫码 |
| `.feishu_session.json` | 程序缓存的 cookie **副本** | 程序下次重新去浏览器取 |

关键就在这：**只删 `.feishu_session.json` 是没用的**。程序会重新打开浏览器去取
凭证，而浏览器自己还记着登录，于是取回来的还是同一份 —— 看起来就像「删了没生效」。

一条命令同时清掉两个，然后继续正常流程（会弹浏览器让你重新登录）：

```bash
uv run python main.py --reset
```

> 手动删也行，但要**先关掉浏览器窗口**，否则文件被占用删不掉。

### 文件名里哪些字符会被换掉

标题里的特殊字符统一换成下划线 `_`，避免建不出文件或者看起来像路径。规则是
「半角在该换的名单里，对应的全角也一起换」：

| 类别 | 字符 |
| --- | --- |
| Windows 非法 | `\ / : * ? " < > \|` 及控制字符 |
| 其余符号 | `、 & @ # $ % ^ ( ) [ ] { } ; , ' .` 和反引号 |
| 全角写法 | `。，；：？（）［］｛｝＜＞／＼｜＆＾＄＃＠％＊“”‘’｀` |

```
第1章-Java基础-基础语法、流程控制、方法  →  第1章-Java基础-基础语法_流程控制_方法
6. 接口文档-线索管理                     →  6_接口文档-线索管理
第4章-容器-Array、String&StringBuilder   →  第4章-容器-Array_String_StringBuilder
【重要】说明                             →  【重要】说明（保留）
```

> `-` 是分隔符所以保留；`【】《》` 在中文标题里太常见，刻意不换。
> 结尾的点、空格、下划线会被去掉（Windows 不认以点结尾的文件名）。

### 文档访问密码

带密码的文档**可以自动填充**，机制是：

1. 打开文档 → 检测到密码框
2. 先拿 `config.json` 里的 `password` 试一次
3. 不对或为空 → 问你一次。**两种输入方式同时有效**：
   - 在这个终端窗口里输，或
   - 直接在浏览器窗口的密码框里输

   **谁先完成算谁的**，另一个自动作罢。不用管程序在等哪边 —— 你在浏览器里
   输完进去了，程序会自己发现并继续。
4. 从终端输的密码会**自动写回 `config.json`**，以后每次自动填

所以只需在第一次遇到带密码的文档时输一遍。

> ⚠️ 访问密码**不等于**登录。密码只让你进某一篇，列整棵文档树仍然要登录 ——
> 详见上方「为什么必须登录」。

## 配置 `config.json`

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `root_url` | — | 要下载的文档链接（根文档） |
| `password` | `""` | 页面访问密码，可留空。失效时会提示输入并自动写回 |
| `browser` | `auto` | 用哪个浏览器：`auto`（自动找）/ `chrome` / `msedge` / `custom` / `chromium`。见上方「浏览器与登录」 |
| `browser_path` | `""` | Chromium 内核浏览器的 exe 完整路径。`browser=custom` 时用它，`auto` 下是第三候选 |
| `export_dir` | `downloads` | PDF 输出目录 |
| `concurrency` | `4` | 并发导出任务数。纯 HTTP，不受浏览器标签页限制。被限流就降到 1 |
| `max_retry` | `3` | 单篇失败重试次数 |
| `retry_backoff` | `2.0` | 重试退避基数（秒），按 2s/4s/8s 递增 |
| `poll_interval` | `2.0` | 轮询导出进度的间隔（秒） |
| `export_timeout` | `300` | 单个导出任务最长等待（秒）。服务端自报上限是 600 |
| `export_format` | `pdf` | 导出格式：`pdf` / `word` / `md`（写 `docx`、`markdown` 也认） |
| `export_comment` | `false` | Word/PDF 专用：是否导出正文及评论 |
| `export_attachment` | `true` | Markdown 专用：`true`=带附件的全部内容，`false`=仅文本 |
| `export_src_type` | `docx` | **源文档**类型标识（新版文档为 `docx`），跟导出格式是两回事 |
| `skip_existing` | `true` | 已成功导出且文件完好的文档直接跳过 |
| `min_pdf_chars` | `0` | 正文最少字数，低于此值判失败。**默认 0 即关闭**，详见下方说明 |
| `min_pdf_bytes` | `3072` | PDF 最小字节数 |
| `min_text_bytes` | `16` | Markdown/文本产物最小字节数。**跟 PDF 分开**，别合并 —— 见下方说明 |
| `max_filename_len` | `120` | 文件名最大长度（防 Windows 260 字符路径限制） |
| `page_timeout_ms` | `5000` | 页面元素操作超时（仅登录时用） |
| `nav_timeout_ms` | `60000` | 页面跳转超时（仅登录时用） |
| `api_timeout` | `60` | 单个 HTTP 接口调用超时（秒） |

> 旧版 `config.json` 里的键继续生效，缺失的键用默认值补齐，不用手改配置。
> 已废弃的 `render_*`、`scroll_step_delay`、`sidebar_xpath` 会被原样保留但不参与逻辑。

## 输出与日志

- **导出产物**：保存在 `export_dir`（默认 `downloads/`），**按飞书里的目录结构分文件夹** ——
  文件夹名取自父文档标题，
  文档以自身标题命名。规则一句话：**有子文档的文档会折进一个以自己命名的文件夹，
  自己也待在里面**；没有子文档的就是一个平铺的 PDF。根文档是唯一的特例，它留在顶层：

  ```
  downloads/
    首页.pdf                                    ← 根文档，留在顶层
    第1章-Java基础-基础语法_流程控制_方法/
      第1章-Java基础-基础语法_流程控制_方法.pdf    ← 父文档自己也在这个文件夹里
      作业.pdf
      day01总结.pdf
    第11章-轻客管家-登录校验_线索管理.pdf          ← 没有子文档，平铺
    接口文档/
      接口文档.pdf
      1_接口文档-部门管理.pdf
      ...
  ```

  > 扩展名由导出格式决定（`.pdf` / `.docx` / `.md`）。上面以 PDF 为例。
  >
  > 所以「文件夹名和里面的文件同名」是**正常的** —— 那篇文档既是一篇文档、
  > 又是一个章节的家。用 `--diag` 能看到每篇最终会落到哪个路径。
  >
  > **Markdown 带附件那档还会再包一层**（每篇自己的文件夹，用来装 `图片和附件/`）。
  > 见上方「Markdown『带附件』下下来是个压缩包」。

  同一篇文档（按 node_token 识别）重复导出会覆盖旧文件；同名但不同文档才加 `_2`、`_3` 后缀；
  磁盘上已存在、但不属于本次清单的文件不会被覆盖。
- **`manifest.json`**：增量清单，记录每篇的 token、文件名、大小、sha1、页数、字数、导出时间与状态。
  中断后重跑会自动跳过已完成的；失败的会被记录，下次自动重试。删掉此文件即等于全量重来。

### 会重复下载吗

**默认不会。** 跳过要同时满足六个条件：

1. 清单里有这篇的记录
2. 状态是 `ok`（不是上次失败）
3. 文件**还在**磁盘上
4. **文件大小**和记录一致（被外部改动过就不认）
5. 记录里的**位置和形态**和这次该放的一致（目录规则没变过，也没在
   「扁平 .md」和「装附件包的文件夹」之间切换过）
6. 记录里的**导出选项**和这次一致（格式、带不带评论/附件没变过）

任何一条不满足就会重下 —— 所以「上次失败的」「文件被你删了的」都会自动重来。

> 第 5、6 条是给「改了设置却发现没生效」准备的。这两种情况下老文件都还好好
> 躺在原地，光看前四条会全部放行：
>
> - **位置**：目录规则一改，老记录还指着老位置；
> - **选项**：`downloads/首页.pdf` 这个路径，带评论和不带评论**是同一个**。
>   导过不带评论的再选「带评论」，文件在、大小也对 —— 不加这条就会静默跳过，
>   你拿到的还是旧的那份。
>
> ⚠️ 重下**不会**删掉老位置的文件 —— 本工具从不主动删你磁盘上的东西。
> 所以换过目录规则之后，老文件会原地留着，看起来像多出来一份，确认新文件没问题后
> **手动删掉即可**。换导出格式同理（旧格式的文件会留下）。
>
> 换 `export_dir` 也会整轮重下：清单里存的是**相对**路径，换了根目录就对不上了。
> 这不是错误，只是白跑一趟。
>
> 老清单里的 `file` 是纯文件名、也没有选项字段，新清单存相对路径加选项签名，
> 两种都读得懂。

> ⚠️ 但它**不检测飞书上的文档有没有更新**。文档改了内容、你本地文件还在，
> 它照样跳过。想强制全部重下就用 `--force`。
- **`.feishu_session.json`**：登录凭证缓存，**含账号凭证，已在 .gitignore 里，别提交**。
- **`logs/run-<时间戳>.log`**：每次运行的归档日志；`run.log` 始终是最新一次的副本。

## 排查

- **提示「凭证验收没通过：`[920004004] PermFail`」**：浏览器里那个身份列不出文档树。
  绝大多数情况是**其实没登录**（只输过访问密码）。跑一次 `uv run python main.py --reset`，
  在弹出的窗口里**真的扫码登录**。详见上方「为什么必须登录」。
- **提示「凭证验收没通过：`[920004002] SourceNotExist`」**：**不是登录问题**，
  别去 `--reset`（重登多少次都一样）。它的意思是「这个节点不存在」，常见原因：
  文档已被删除、链接复制得不完整、或者账号无权访问（飞书对**无权访问**的节点
  也回「不存在」）。
  > 曾经还有一个原因：从飞书复制的链接带着 `?from=from_copylink`，token 被查询串
  > 污染了。**现在程序会自动剥掉，不用再手动删**（见 `flybook/api.py` 的 `token_of`）。
  >
  > 两个错误码的区别值得记一下：`PermFail` 是「**你是谁**不够格」，
  > `SourceNotExist` 是「**你要的东西**不存在」。程序现在会按错误码分流：
  > 前者提示重登，后者提示改链接 —— 不会再一律打发你去 `--reset` 白折腾一场。
- **明明能打开文档，却提示没登录**：这是**故意的**。能打开单篇不等于能列整棵树，
  见上方「为什么必须登录」。别去改判定逻辑，那是专门为了不再少导出才加的。
- **拿不到登录凭证 / 提示重登后仍失败**：跑 `uv run python main.py --relogin` 重新登录一次。
- **删了 `.feishu_session.json` 却还是登录状态**：正常现象 —— 真正的登录态在
  `.browser_profile/`。用 `uv run python main.py --reset` 把两个一起清掉。
- **浏览器起不来**：启动日志会逐个列出尝试结果和失败原因。换 `browser` 试别的
  （例如 `"browser": "msedge"`），或者装一下 Chrome / Edge。
- **明明登录过却还要重登**：多半是**换了浏览器** —— profile 按浏览器分开存，
  换一个就得重登一次。也可能是凭证过期了，重登即可。
- **`--diag` 里文档树是空的**：说明接口变了或权限有调整，见下方「内部接口」一节。
- **日志里出现「退回浏览器旁听兜底」**：接口这条路走不通了（不是登录问题 ——
  凭证是先验收过才用的）。旁听通常只拿得到第一层，**篇数会明显偏少**，
  拿 `--diag` 核对过再用。
- **篇数明显偏少，但日志一切正常**：先确认给的是不是**最顶层的根文档**。
  工具只从你给的那一篇往下递归，给中间某篇就只导它那棵子树，而且不报错。
  拿 `--diag` 看文档树有几篇、根文档标题对不对，见上方「链接怎么给」。
- **换了格式/选项，怎么没重新导出**：正常不会。清单里记了导出选项，选项一变
  就会重下。如果真没重下，看日志开头那行「导出格式」是不是你以为的那个 ——
  命令行参数会写回 `config.json`，容易被上次的设置延续。
- **换格式后磁盘上多出一份旧的**：本工具不删文件，旧格式的产物会原地留着
  （`首页.pdf` 和 `首页.md` 会共存）。确认新的没问题后手动删掉旧的。
- **某篇反复失败**：看 `logs/` 里对应日志的失败原因，多数是网络抖动，重跑即可。
- **被限流**：把 `concurrency` 降到 `1`，`poll_interval` 适当调大。
- **导出结果内容偏少**：日志里每篇都会打印「N 页 / M 字」。真觉得可疑就把 `min_pdf_chars`
  调大（例如 `50`），让字数不足的产物直接判失败。注意**内容本来就少的文档会被误伤**——
  实测「其他资料」就是个 1 页 5 字的空目录页。
- **Markdown 全判失败了，日志说「文件过小」**：`min_pdf_bytes` 和 `min_text_bytes`
  是**两个**门槛，按当前格式自动选。它们不能合并 —— Markdown 本来就短，
  实测知识库根文档的正文只有 467 字节且内容正常，套 PDF 的 3072 会被整批误杀。
  真被误杀就调小 `min_text_bytes`。

## 实现说明


### 文档树是递归抓的

`get_info` 这个接口**每次只返回一层** —— 你给它的那个节点，加上它的直接子节点，
再往下就没有了。

早期版本只调了一次就把结果当成整棵树，于是**整个库只导出到第一层**。实测一个
41 篇的知识库只下来了 15 篇，`接口文档` 底下的 9 篇、各章节的 `作业` / `总结`
一篇都没抓到 —— 而且不报错，看起来完全正常。

现在改成 BFS 逐层展开（`collector.probe_via_api`）：从根文档开始，拿到子节点后
把它们再排进队列继续问，直到没有新节点为止。带上 `seen` 去重防成环，2000 篇
封顶兜底。判断还有没有下一层可以看 `has_child` 字段，但代码不去信它 ——
直接问一遍，返回空列表就是到底了。

### 异步任务

```
1. POST /space/api/export/create/          提交任务 → ticket
2. GET  /space/api/export/result/<ticket>  轮询 job_status（0=成功 1=失败 2=处理中）
3. GET  .../box/stream/download/all/<file_token>/   下载成品
4. 校验产物（PDF 读页数字数；docx 验 ZIP 头；md 验能解出文本）
```

只做第 1 步是不够的 —— `ticket` 只是一张收据，文件要等服务端渲染完才有。
