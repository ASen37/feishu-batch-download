# 飞书文档批量导出

将飞书知识库中的文档及其子文档**递归**导出为 PDF / Word / Markdown，并按飞书目录结构分文件夹保存。产物由飞书服务端渲染，与网页端手动导出内容**逐字一致**。

自 v0.3 起，工具改为**调用飞书原生导出接口**：浏览器仅在首次登录时使用一次，此后所有操作（获取文档树、提交导出任务、轮询状态、下载文件）均通过纯 HTTP 完成，无需渲染页面。导出十几篇文档由「逐篇打开页面等待渲染」变为「一轮并发请求」。

支持导出正文评论、Markdown 携带附件（正文与图片打包，自动解压）等选项，详见「导出格式」。

## 使用前提

1. 已安装 [uv](https://docs.astral.sh/uv/)。
2. 本机网络可访问飞书。
3. 本机已安装 Chrome 或 Edge（Windows 自带 Edge，通常无需额外安装）。
4. **拥有可访问目标知识库的飞书账号**，首次运行需在弹出的浏览器窗口中登录一次。

> **注意**：必须完成真实登录，仅输入访问密码不足，原因见「为何必须登录」。

## 初始化

**仅需安装 Python 依赖；浏览器使用本机 Chrome / Edge，无需下载内核：**

```bash
uv sync
```

> 仅当需要使用 Playwright 自带内核时（`browser` 设为 `chromium`，或本机既无 Chrome 也无 Edge），才需额外执行：
>
> ```bash
> uv run playwright install chromium
> ```

## 使用

### 链接选择：提供最顶层的根文档

工具从给定文档开始**向下递归**，链接选择会直接影响导出结果，运行前请先确认：

**请提供最顶层的根文档。** 若提供中间层文档，则只会导出该文档下的子树，同级兄弟章节均不会被导出，且**不会报错**，表现与正常完成一致。可打开知识库，左侧目录树中最上方的一篇（通常为「首页」）即根文档。

> 飞书「复制链接」生成的地址带有 `?from=from_copylink` 查询参数，**无需手动处理**，程序会自动移除。若出现 `[920004002] SourceNotExist`，属于其他原因，见「排查」。
>
> 在命令行传入链接时，建议使用**引号**包裹：链接中的 `&` 在部分终端中会被识别为分隔符。

### 1. 交互式启动：双击 `start.bat`

启动后会依次询问要导出的链接，然后自动执行。首次运行需在弹出的浏览器中登录飞书账号。窗口在结束前会暂停，便于查看结果。

```
start.bat                 双击运行，或命令行直接运行
start.bat <文档链接>       直接指定链接，跳过询问
start.bat --force         参数原样透传给 main.py
```

### 2. 命令行方式

**首次运行（有头模式，需手动登录一次）：**

```bash
uv run python main.py
```

浏览器弹出后登录飞书账号；**程序会自动检测登录完成，无需按回车**。凭证缓存至 `.feishu_session.json`，浏览器关闭，后续操作全部通过 HTTP 完成。

**后续运行（不再弹出浏览器）：**

```bash
uv run python main.py
```

**更换下载链接：**

```bash
uv run python main.py <新链接>
```

新链接会自动写入 `config.json`，后续直接运行 `python main.py` 即可。

### 3. 命令行参数

```
uv run python main.py [文档链接] [参数]
```

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `<文档链接>` | 指定要下载的根文档 | 写入 `config.json`；未提供时使用已保存的链接 |
| `--format` | 导出格式：`pdf` / `word` / `md` | 也接受 `docx`、`markdown` |
| `--comments` | Word/PDF：**导出正文及评论** | 默认不包含评论 |
| `--no-comments` | Word/PDF：仅正文（默认） | |
| `--attachments` | Markdown：**带附件的全部内容**（默认） | 包含图片与附件 |
| `--no-attachments` | Markdown：仅文本 | 不包含图片与附件 |
| `--out` | 本地保存目录 | 默认 `downloads`；相对路径基于程序所在目录 |
| `--force` | 忽略增量清单，**全部重新下载** | 已下载且文件仍存在的文档同样重新导出 |
| `--relogin` | 丢弃**凭证缓存**，强制重新登录 | 仅清除 `.feishu_session.json`，**不影响浏览器登录态** |
| `--reset` | 清空**全部登录状态**，完全重置 | 同时清除凭证与浏览器 profile，详见下文 |
| `--diag` | 仅查询文档树并打印节点表，**不下载** | 用于排查「无法抓取文档」问题，会列出每篇文档的 obj_token |
| — | `--diag` **并非完全只读** | 若在命令行传入链接，该链接会被写回 `config.json`；使用其他链接进行诊断会覆盖当前配置 |
| `--headless` | 无头模式 | 浏览器不显示窗口，仅在需要登录时使用 |
| `-h`, `--help` | 显示帮助 | |

> `--format` / `--comments` / `--attachments` / `--out` 一经指定便会**写回 `config.json`**，下次不带参数运行时沿用。双击 `start.bat` 时也会以问答方式询问相同选项。

### 导出格式

| 格式 | 命令行 | 产物 | 该格式的选项 |
| --- | --- | --- | --- |
| PDF | `--format pdf` | `.pdf` | `--comments` / `--no-comments` |
| Word | `--format word` | `.docx` | 同上 |
| Markdown | `--format md` | `.md` | `--attachments` / `--no-attachments` |

各项默认值按常用场景设定：**Word/PDF 不包含评论，Markdown 包含带附件的全部内容。** 两种格式的选项相互独立：导出 Markdown 时评论开关不参与，反之亦然，因此切换格式不会触发不必要的重复下载。

#### Markdown「带附件」的产物为压缩包

选择「带附件的全部内容」时，飞书返回的是 **zip** 文件，而非 `.md`：

```
预习任务-提前安装软件.zip
├── 预习任务-提前安装软件.md      ← 正文
└── 图片和附件/image.png          ← 47 张图
```

程序会**自动解压**，并将正文重命名为与文件夹同名，保存在文档自身的文件夹中：

```
downloads/Day01_项目环境-Linux/
└── 预习任务-提前安装软件/
    ├── 预习任务-提前安装软件.md    ← 图片链接相对指向 图片和附件/，解压后仍可访问
    └── 图片和附件/
        └── …47 张
```

**每篇文档使用独立文件夹的原因**：压缩包内的附件目录名称**固定**为「图片和附件」。若两篇文档位于同一父目录，图片会互相覆盖。这与「含子文档的父文档收入自身文件夹」的设计一致。

**注意**：`--no-attachments`（仅文本）保持为单个扁平 `.md` 文件，不再套用文件夹，因为无附件时不存在命名冲突。

> 另外，**同一选项下产物形态可能不同**。没有图片或附件的文档即使选择「带附件的全部内容」，飞书返回的仍是普通 `.md`。程序依据选项决定落点（多包一层文件夹），依据**文件头**决定是否解压，两者分别处理，因此有无附件均可正确处理。

#### 思维导图 / 画板文档：Markdown 无法导出，自动转换为图片

知识库中**整篇为一张思维导图（画板）**的文档（常见于各章的「总结」「day01总结」）在导出为 Markdown 时，飞书返回的是**空壳**：

```
# 总结          ← 10 个字节，正文无内容，且不报错
```

早期版本将其视为「文件过小」判定失败，导致每轮重试均失败。实际情况是**该格式无法导出画板内容**，重试无法解决。当前处理流程：

1. 检测到 Markdown 正文去除标题后无内容，判定为「整篇为画板」；
2. 改为导出 PDF，并将内嵌图片**按原始字节提取**（飞书渲染结果为 2560×2560 JPEG，直接复制字节，不重新编码，不损失画质）；
3. 图片保存为 `<同名>.jpg`，同时将 `.md` 改写为引用该图片：

```
第5章-匿名内部类_lambda_Stream_异常_Maven/
└── 总结/
    ├── 总结.md     ← # 总结 + ![](总结.jpg)，不再是空壳
    └── 总结.jpg    ← 完整的思维导图
```

**无法提取位图时，保留完整 PDF**，并将 `.md` 改为指向该 PDF：

```
接口文档/
├── 接口文档.md     ← # 接口文档 + [接口文档](接口文档.pdf)
└── 接口文档.pdf    ← 矢量画板，无法提取「图片」，但内容完整
```

边界说明：

- **仅对 Markdown 格式生效**。PDF 与 Word 导出的产物本身包含图片，无需兜底处理。
- 提取的图片为 **JPEG**，而非 PNG。服务端本身使用 JPEG 渲染，原样复制可保证画质。（飞书网页端的「下载为图片」由前端 canvas 绘制；服务端**不提供**图片导出接口，实测 `png/jpg/svg` 扩展名均被拒绝：`[1018] export file extension mismatch`。）
- 触发条件为「整篇为画板」。**正文包含文字并内嵌画板**的文档不在覆盖范围内：此类文档的 Markdown 含正文，无法判定为空，内嵌画板仍会丢失。
- **不会判定「文档为空」**，原因见下。
- 如需关闭此兜底逻辑，设置 `"mindmap_to_image": false`。

> **为何没有「空文档」判定**：实测同一篇画板文档连续导出三次 PDF，内容流大小分别为 860 / 5900 / 16322 字节，**服务端渲染结果不稳定**。860 字节的版本仅包含白底与标题，与「无内容」的表现一致。早期版本据此将「接口文档」判为空文档并放行，实际丢失了一张图片。
>
> 因此当前策略为：无法提取位图时**多次导出，保留内容最完整的版本**，并且无论哪一版均**保留 PDF**。误判为「多一个无用 PDF」仅多占几 KB，误判为「空」则会丢失内容；在两者之间选择可接受的误判方向。

```bash
uv run python main.py --format md                    # 导出为 Markdown（默认带附件）
uv run python main.py --format word --comments       # 导出为 Word，包含评论
uv run python main.py --format pdf --out D:\飞书文档   # 更换保存目录
```

可组合使用：

```bash
uv run python main.py                    # 使用 config.json 中保存的链接
uv run python main.py <新链接>            # 更换链接下载
uv run python main.py --force            # 全部重新下载
uv run python main.py <新链接> --diag     # 先查看该链接下的文档树
uv run python main.py --reset            # 完全重置（清空登录状态）
```

## 浏览器与登录

### 浏览器选择

由 `config.json` 中的 `browser` 决定，默认 `auto`，即**按顺序自动选择第一个可用的浏览器**：

| 顺序 | 值 | 说明 |
| --- | --- | --- |
| 1 | `chrome` | 本机 Google Chrome |
| 2 | `msedge` | 本机 Microsoft Edge（Windows 自带，通常无需安装） |
| 3 | `custom` | `browser_path` 指向的 Chromium 内核浏览器 |
| 4 | `chromium` | Playwright 自带内核（需 `playwright install chromium`） |

也可强制指定，例如 `"browser": "msedge"`。若填写未知值，或 `custom` 未配置 `browser_path`，会自动回退到 `auto`，并在日志中说明原因。

启动日志会明确记录最终使用的浏览器：

```
正在启动浏览器
  候选顺序：本机 Google Chrome → 本机 Microsoft Edge → Playwright 自带 Chromium
  ✗ 本机 Google Chrome 起不来：...
浏览器启动完成（本机 Microsoft Edge）。
```

> **不保证支持第三方浏览器**（360、QQ 等）。Playwright 仅支持 chrome / msedge / chromium 官方渠道；通过 `browser_path` 强制指定或许可以运行，但不受支持，出现问题难以排查。

### 登录状态相互独立

程序使用**独立的用户数据目录**（`.browser_profile/`），与日常使用的浏览器**不共享登录状态**。

因此，「Chrome 中已登录飞书」**不生效**，必须在弹出的窗口中**重新登录**。仅需一次，之后凭证缓存于 `.feishu_session.json`，正常情况下不再弹出窗口。

各浏览器的 profile 分开存放（Chrome 使用 `.browser_profile/`，其他浏览器使用 `.browser_profile/<浏览器名>/`），避免不同浏览器的 profile 格式冲突。**更换浏览器后需重新登录一次。**

### 为何必须登录（仅输入访问密码不足）

部分知识库**输入访问密码即可匿名阅读**，未登录也能打开其中的单篇文档，正文显示与登录后一致。

但匿名身份存在限制：**无法列出完整文档树**。

| 操作 | 匿名读者（仅输入访问密码） | 已登录成员 |
| --- | --- | --- |
| 打开单篇文档 | 支持 | 支持 |
| 列出知识库文档树 | 不支持（`[920004004] PermFail`） | 支持 |

本工具依赖「列出文档树」发现子文档；无法获取文档树时只能导出第一层。实测某 41 篇文档的知识库中，匿名身份仅导出 15 篇，**且不报错**，表现与正常运行一致。

因此程序会**主动验证登录态**，并对获取的凭证进行**验收**：

- 打开文档前，先访问一个必须登录才能访问的页面，确认身份有效；
- 未登录时将浏览器停留在登录页，等待扫码或输入手机号，登录完成后自动继续；
- 获取凭证后立即真实调用一次文档树接口；若无法列出则重试，始终失败则**停止并报错**，不会使用无效身份继续执行。

> 简而言之：**访问密码是单篇文档的入口，登录身份才是访问整个知识库的凭证。**

### 清空登录状态并重新开始

登录状态保存在**两个位置**，仅删除其中一个通常无效：

| 位置 | 内容 | 删除后的结果 |
| --- | --- | --- |
| `.browser_profile/` | 浏览器 profile，**真实登录态存放于此** | 浏览器恢复未登录状态，需重新扫码 |
| `.feishu_session.json` | 程序缓存的 cookie **副本** | 程序下次会重新从浏览器获取 |

关键在于：**仅删除 `.feishu_session.json` 无效**。程序会重新打开浏览器获取凭证，而浏览器仍保留登录状态，获取到的仍是同一份凭证，表现为「删除未生效」。

使用一条命令同时清除两者，并继续正常流程（会弹出浏览器要求重新登录）：

```bash
uv run python main.py --reset
```

> 也可手动删除，但需**先关闭浏览器窗口**，否则文件被占用无法删除。

### 文件名中的字符替换规则

标题中的特殊字符统一替换为下划线 `_`，以避免无法创建文件或产生路径歧义。规则为「半角字符若在替换名单中，对应全角字符一并替换」：

| 类别 | 字符 |
| --- | --- |
| Windows 非法 | `\ / : * ? " < > \|` 及控制字符 |
| 其余符号 | `、 & @ # $ % ^ ( ) [ ] { } ; , ' .` 和反引号 |
| 全角写法 | `。，；：？（）［］｛｝＜＞／＼｜＆＾＄＃＠％＊“”‘’｀` |

```
第1章-Java基础-基础语法、流程控制、方法  →  第1章-Java基础-基础语法_流程控制_方法
6. 接口文档-线索管理                     →  6_接口文档-线索管理
第4章-容器-Array、String&StringBuilder   →  第4章-容器-Array_String_StringBuilder
【重要】说明                             →  【重要】说明（保留）
```

> `-` 为分隔符，因此保留；`【】《》` 在中文标题中较常见，不做替换。末尾的点、空格和下划线会被移除（Windows 不支持以点结尾的文件名）。

### 文档访问密码

带密码的文档**支持自动填充**，机制如下：

1. 打开文档，检测密码输入框；
2. 先使用 `config.json` 中的 `password` 尝试；
3. 密码错误或为空时，提示输入一次。**两种输入方式均有效**：
   - 在终端窗口中输入，或
   - 直接在浏览器窗口的密码框中输入

   **以先完成者为准**，另一方式自动终止。无需关注程序等待哪一侧：在浏览器中完成输入后，程序会自动检测并继续。
4. 从终端输入的密码会**自动写回 `config.json`**，后续自动填充。

因此只需在首次遇到带密码文档时输入一次。

> **注意**：访问密码**不同于**登录。密码仅用于访问单篇文档，列出完整文档树仍需要登录，详见「为何必须登录」。

## 配置 `config.json`

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `root_url` | — | 要下载的文档链接（根文档） |
| `password` | `""` | 页面访问密码，可留空。失效时会提示输入并自动写回 |
| `browser` | `auto` | 使用的浏览器：`auto`（自动查找）/ `chrome` / `msedge` / `custom` / `chromium`。见「浏览器与登录」 |
| `browser_path` | `""` | Chromium 内核浏览器的 exe 完整路径。`browser=custom` 时使用，`auto` 下为第三候选 |
| `export_dir` | `downloads` | 导出产物目录 |
| `concurrency` | `4` | 并发导出任务数。纯 HTTP，不受浏览器标签页限制。被限流时降至 1 |
| `max_retry` | `3` | 单篇文档失败重试次数（遇到 429 时自动额外增加 2 次，见下） |
| `retry_backoff` | `2.0` | 重试退避基数（秒），按 2s/4s/8s 递增 |
| `retry_429_backoff` | `8.0` | **429 专用**退避基数（秒）。配额窗口以分钟计，2s/4s 的节奏不足以避开限制 |
| `api_min_interval` | `0.25` | 两次接口请求起点的最小间隔（秒）。并发数不影响该限制 |
| `api_max_interval` | `4.0` | 遇到 429 后间隔上限。触发一次翻倍，连续成功 20 次后逐步回退 |
| `mindmap_to_image` | `true` | Markdown 格式：整篇为思维导图/画板时自动转换为图片，见上文说明 |
| `poll_interval` | `2.0` | 轮询导出进度的间隔（秒） |
| `export_timeout` | `300` | 单个导出任务最长等待时间（秒）。服务端自报上限为 600 |
| `export_format` | `pdf` | 导出格式：`pdf` / `word` / `md`（也接受 `docx`、`markdown`） |
| `export_comment` | `false` | Word/PDF 专用：是否导出正文及评论 |
| `export_attachment` | `true` | Markdown 专用：`true`=带附件的全部内容，`false`=仅文本 |
| `export_src_type` | `docx` | **源文档**类型标识（新版文档为 `docx`），与导出格式无关 |
| `skip_existing` | `true` | 已成功导出且文件完好的文档直接跳过 |
| `min_pdf_chars` | `0` | 正文最少字数，低于此值判失败。**默认 0 即关闭**，详见下方说明 |
| `min_pdf_bytes` | `3072` | PDF 最小字节数 |
| `min_text_bytes` | `16` | Markdown/文本产物最小字节数。**与 PDF 分开设置**，不可合并，见下方说明 |
| `max_filename_len` | `120` | 文件名最大长度（避免 Windows 260 字符路径限制） |
| `page_timeout_ms` | `5000` | 页面元素操作超时（仅登录时使用） |
| `nav_timeout_ms` | `60000` | 页面跳转超时（仅登录时使用） |
| `api_timeout` | `60` | 单个 HTTP 接口调用超时（秒） |

> 旧版 `config.json` 中的键仍然生效，缺失的键使用默认值补齐，无需手动修改。已废弃的 `render_*`、`scroll_step_delay`、`sidebar_xpath` 会原样保留，但不参与逻辑。

## 输出与日志

- **导出产物**：保存在 `export_dir`（默认 `downloads/`），**按飞书目录结构分文件夹**：文件夹名取自父文档标题，文档以自身标题命名。规则如下：**含子文档的文档收入以自身命名的文件夹，并存放在其中**；无子文档的文档直接平铺。根文档是唯一例外，保留在顶层：

  ```
  downloads/
    首页.pdf                                    ← 根文档，保留在顶层
    第1章-Java基础-基础语法_流程控制_方法/
      第1章-Java基础-基础语法_流程控制_方法.pdf    ← 父文档也位于该文件夹内
      作业.pdf
      day01总结.pdf
    第11章-轻客管家-登录校验_线索管理.pdf          ← 无子文档，平铺
    接口文档/
      接口文档.pdf
      1_接口文档-部门管理.pdf
      ...
  ```

  > 扩展名由导出格式决定（`.pdf` / `.docx` / `.md`）。上例以 PDF 为例。
  >
  > 因此「文件夹名与内部文件同名」是**正常现象**：该文档既是独立文档，也是章节的容器。使用 `--diag` 可查看每篇文档的最终路径。
  >
  > **Markdown 带附件模式会额外套一层文件夹**（每篇文档独立文件夹，用于存放 `图片和附件/`）。详见「Markdown『带附件』的产物为压缩包」。

  同一篇文档（按 node_token 识别）重复导出会覆盖旧文件；同名但不同文档才会追加 `_2`、`_3` 后缀；磁盘上已存在但不属于本次清单的文件不会被覆盖。
- **`manifest.json`**：增量清单，记录每篇文档的 token、文件名、大小、sha1、页数、字数、导出时间与状态。中断后重新运行会自动跳过已完成项；失败项会被记录，下次自动重试。删除该文件即等同于全量重跑。

### 是否会重复下载

**默认不会。** 跳过需同时满足以下条件：

1. 清单中存在该文档的记录；
2. 状态为 `ok`（非上次失败）；
3. 文件**仍存在于磁盘**；
4. **文件大小**与记录一致（被外部修改则不认可）；
5. 记录中的**位置与形态**与本次预期一致（目录规则未变，且未在「扁平 .md」与「附件文件夹」之间切换）；
6. 记录中的**导出选项**与本次一致（格式、是否包含评论/附件未变）；
7. Markdown 格式另有两条规则，用于处理「旧版本遗留的可疑记录」：
   - **字数异常少且未标记 `kind`**：思维导图文档在加入兜底逻辑前被导出为 10 字节空壳 md 并记录为 `ok`，文件存在且大小正确，仅依赖前六条会全部放行，导致**修复后仍永远不会重新导出**；
   - **`kind` 为 `doc` 但字数为 0**：由「空文档」这一错误结论遗留（该结论已删除，见「思维导图 / 画板文档」）。

   上述两类仅会重新检查一次，之后会带上正确的 `kind`，不再重复触发。

任一条件不满足都会重新下载，因此「上次失败」「文件被删除」的情况都会自动重试。

> 第 5、6 条用于避免「修改设置后未生效」。这两种情况下旧文件仍保留在原位，仅依赖前四条会全部放行：
>
> - **位置**：目录规则变更后，旧记录仍指向旧位置；
> - **选项**：`downloads/首页.pdf` 这一路径在带评论与不带评论时**完全相同**。若先导出不带评论的版本，再选择「带评论」，文件存在且大小正确，缺少此条件会静默跳过，最终得到的仍是旧文件。
>
> **注意**：重新下载**不会**删除旧位置的文件，本工具不会主动删除磁盘上的任何内容。因此更换目录规则后，旧文件会保留在原位，看起来像多出一份；确认新文件无误后，**手动删除即可**。更换导出格式同理（旧格式文件会保留）。
>
> 更换 `export_dir` 会导致整轮重新下载：清单中保存的是**相对**路径，根目录变更后无法对应。这不属于错误，只是重复执行一次。
>
> 旧清单中的 `file` 为纯文件名，且没有选项字段；新清单保存相对路径与选项签名，两种格式均可读取。

> **注意**：本工具**不检测飞书文档是否更新**。若文档内容已修改但本地文件仍存在，仍会跳过。需要强制全量重新下载时使用 `--force`。

- **`.feishu_session.json`**：登录凭证缓存，**包含账号凭证，已在 .gitignore 中，请勿提交**。
- **`logs/run-<时间戳>.log`**：每次运行的归档日志；`run.log` 始终为最新一次的副本。

## 排查

- **提示「凭证验收没通过：`[920004004] PermFail`」**：浏览器中的身份无法列出文档树。绝大多数情况是**实际未登录**（仅输入过访问密码）。执行 `uv run python main.py --reset`，在弹出的窗口中完成扫码登录。详见「为何必须登录」。
- **提示「凭证验收没通过：`[920004002] SourceNotExist`」**：**不是登录问题**，不要执行 `--reset`（重新登录无法解决）。该错误表示「节点不存在」，常见原因：文档已被删除、链接复制不完整，或账号无权访问（飞书对**无权访问**的节点同样返回「不存在」）。

  > 此外，历史上还有另一原因：从飞书复制的链接带有 `?from=from_copylink`，导致 token 被查询串污染。**当前程序会自动移除，无需手动处理**（见 `flybook/api.py` 的 `token_of`）。
  >
  > 两个错误码的区别值得注意：`PermFail` 表示「**身份**不具备权限」，`SourceNotExist` 表示「**目标**不存在」。程序会按错误码分流：前者提示重新登录，后者提示修改链接，不再统一要求执行 `--reset`。

- **可以打开文档，但提示未登录**：这是**有意设计**。能够打开单篇文档不代表能够列出完整文档树，详见「为何必须登录」。请勿修改判定逻辑，该逻辑用于避免导出遗漏。
- **无法获取登录凭证 / 重新登录后仍失败**：执行 `uv run python main.py --relogin` 重新登录一次。
- **删除 `.feishu_session.json` 后仍为登录状态**：属于正常现象，真实登录态保存在 `.browser_profile/`。使用 `uv run python main.py --reset` 同时清除两者。
- **浏览器无法启动**：启动日志会逐项列出尝试结果与失败原因。尝试更换 `browser`（例如 `"browser": "msedge"`），或安装 Chrome / Edge。
- **已登录却仍要求重新登录**：通常是因为**更换了浏览器**，profile 按浏览器分开保存，更换后需重新登录一次；也可能是凭证过期，重新登录即可。
- **`--diag` 文档树为空**：说明接口发生变化或权限有调整，见「实现说明」一节。
- **日志出现「退回浏览器旁听兜底」**：接口方式不可用（非登录问题，凭证在使用前已通过验收）。旁听通常只能获取第一层，**文档数量会明显偏少**，请先使用 `--diag` 核对。
- **文档数量明显偏少，但日志正常**：先确认提供的是否为**最顶层的根文档**。工具仅从给定文档向下递归，提供中间层文档只会导出对应子树，且不会报错。使用 `--diag` 查看文档树数量与根文档标题，详见「链接选择」。
- **更换格式或选项后未重新导出**：正常情况下不应发生。清单中记录了导出选项，选项变更后会重新下载。若确实未重新下载，请检查日志开头的「导出格式」是否符合预期：命令行参数会写回 `config.json`，可能沿用了上次的设置。
- **更换格式后磁盘上出现旧文件**：本工具不删除文件，旧格式产物会保留（`首页.pdf` 与 `首页.md` 会共存）。确认新文件无误后手动删除旧文件。
- **某篇文档反复失败**：查看 `logs/` 中对应日志的失败原因，多数为网络波动，重新运行即可。
- **日志出现「整篇是一张思维导图，改导 PDF 抠图」**：这是**正常行为**，不是错误。说明该文档为画板类文档，Markdown 无法导出内容，程序已自动改走 PDF 图片提取。
- **某个文件夹中同时存在 `.md` 和 `.pdf`**：该文档为**矢量画板**，无法提取「图片」，因此保留了服务端渲染的完整 PDF。这是**有意设计**：无法提取图片不代表没有内容。
- **日志出现「再导一次 —— 只留内容最全的那版」**：服务端对画板的渲染结果不稳定，程序会多次导出并选择内容最完整的版本。同一篇文档最多导出 3 次，之后不再重复。
- **被限流（HTTP 429）**：这是**累计配额**耗尽，而非每秒请求速率过高。实测单独连续调用 25 次 `export/create` 不会触发，但一次运行累计 58 个导出任务会在后半段被拦截。程序会自动处理：触发后全体退让（`api_min_interval` 翻倍，上限为 `api_max_interval`），退避按 `retry_429_backoff` 以 8s/16s/32s… 递增，连续成功 20 次后逐步恢复。若曾被限流，汇总中会多出一行「接口限流：限流间隔 0.25s→0.5s（429 退让 N 次）」。如仍觉得过慢，可将 `concurrency` 降至 `1`，并调大 `api_min_interval`。
- **导出结果内容偏少**：日志中每篇文档都会打印「N 页 / M 字」。如确有疑问，可调大 `min_pdf_chars`（例如 `50`），使字数不足的产物直接判为失败。注意**内容本身较少的文档会被误判**：实测「其他资料」为 1 页 5 字的空目录页。
- **Markdown 全部判为失败，日志提示「文件过小」**：`min_pdf_bytes` 与 `min_text_bytes` 是**两个**独立阈值，按当前格式自动选择。二者不能合并：Markdown 内容本身较短，实测知识库根文档正文仅 467 字节且内容正常，若套用 PDF 的 3072 阈值会整批误判。若发生误判，请调小 `min_text_bytes`。

## 实现说明

### 文档树采用递归抓取

`get_info` 接口**每次仅返回一层**：给定节点及其直接子节点，不再向下展开。

早期版本仅调用一次便将结果视为完整文档树，导致**整个知识库只导出第一层**。实测某 41 篇文档的知识库仅导出 15 篇，`接口文档` 下的 9 篇以及各章的 `作业` / `总结` 均未抓取，且不报错，表现完全正常。

当前采用 BFS 逐层展开（`collector.probe_via_api`）：从根文档开始，获取子节点后加入队列继续查询，直到没有新节点为止。使用 `seen` 去重以防止成环，上限 2000 篇。判断是否存在下一层可参考 `has_child` 字段，但代码不依赖该字段：直接发起查询，返回空列表即表示已到底。

### 异步任务

```
1. POST /space/api/export/create/          提交任务 → ticket
2. GET  /space/api/export/result/<ticket>  轮询 job_status（0=成功 1=失败 2=处理中）
3. GET  .../box/stream/download/all/<file_token>/   下载产物
4. 校验产物（PDF 读取页数与字数；docx 校验 ZIP 头；md 校验可解析文本）
```

仅执行第 1 步不足够：`ticket` 仅是任务凭据，文件需等待服务端渲染完成后才可获取。
